# 合成資料設計覆核（推論期間記錄）

這是實作者對構造與程式的覆核，**不是獨立人工或 LLM 標註**。不修改已凍結資料。

- 每種 T6 形式確實對應 30 個不同 base_id；五骨架中英各 42 段，包含文件集底稿。
  但 30 個底稿主要由 5 骨架 × 6 主題組成，狀態事實片語仍共用，不能當成 30 個獨立自然語言樣本。
- T6 的 word 是局部詞組變更，英文 `already` → `not yet` 等並非單一 token 對單一 token。
  暫停／資源不足映射到四類中的卡關，是本合成標註的假設；沒有外部覆核其專案語境。
- T3-word 修改中性記錄用詞，沒有完整涵蓋「狀態句本身的同義改述」。
  因此 C 對這種 benign 控制的高分差距，不等於已排除所有詞彙捷徑。
- T4/T5 的確同樣改一字，但所有日期對固定為 11-15 → 11-16／11-25、截止 11-20。
  這沒有反平衡所有日期數字，也沒有涵蓋日期格式差異；B 的日期 AUROC 可能受數字 token 距離影響。
- T5 只改日期而保留原先「進度領先」文字，形成衝突證據。不能把這格分數當成純日期推理測驗。
- T8-sentence 新增阻礙句；T3-sentence 是中性句改述，並非新增相同字數的中性句。
  T8-paragraph 新增一段；T3-paragraph 重排／改骨架。只匹配底稿與名義強度，未等化編輯操作或字數。
  A/B 的結果尤其可能受這個因素影響。T9 刪除狀態句的意義不確定，主表排除、另作敏感度表。
- 主表正例均往風險增加的方向；沒有既有風險維持不變或風險解除的完整配對。
  D2/J single 的當前風險分類即使高分，也無法據此證明一般漂移偵測不需 old。
- T10 標註由「三種信號同時出現」的 metadata 政策構成，政策沒有給模型。
  這批資料只能評估對該合成構造的反應；不能宣稱已測到經獨立判讀成立的瀰散型語意改變。
- 文件集正例的三種修改與負例的中性用詞替換，操作分布也不相同。
  聚合 AUROC 高並不足以證明模型掌握跨段政策；須同時檢視段落觸發率及上述混淆因素。

下一輪若要排除這些混淆，應另開資料版本，預先反平衡日期、加入狀態句良性改述與等量新增控制、
加入既有風險不變／風險解除配對，並取得獨立判讀。這些都不回填本輪已凍結的 H1–H11 結果。
