### 敏感度：排除盲判者自行標記為歧義的 41 段

26B 對 E4B 的整體差距從 +4.9 點縮小為 +3.0 點（97.8 對 94.8）。

E4B 的錯誤有一部分集中在「暫停算卡關」、「剛好在期限當天」這類邊界題。這張表只做描述，不改變上面的判讀。

## 怎麼解讀

1. **v0.3 有鑑別力，但沒達到預先寫死的門檻。**
   - 階梯一路往上：E2B 80.2 → E4B 92.5 → 26B 97.4 → GD1 98.4，沒有任何題型讓 E2B 拿到 95% 以上，跟 v2.1 全部 AUROC ≈ 1 的天花板完全不同。
   - 26B 對 E4B 的整體差距 +4.9 點，統計上很清楚（p = 0.0001），但比預先登記的 5 點門檻少 0.1 點。照凍結規則只能寫「顯著，但未達門檻」。
   - 可以確定成立的是 **G3（日期＋長文件）26B 明顯較高**。
2. **本機判讀層用 J-26B 就夠，它和 GD1 判讀為相當。**
   - 26B：97.4%，L4 上 210 ms，改寫一致率 96%，校準後 ECE 0.008。
   - GD1：準確率只多 0.9 點，差距不顯著，而且要把資料送上雲、無法鎖定版本。
   - 外部評測（Artificial Analysis Symmetry）量到 GD1 的一致性只有 38%，但在這批題目上它有 98%。
3. **E4B 適合當第一道篩選。** 準確率 92.5%，延遲是 26B 的一半；用信心值預測自己答錯的 AUROC 是 0.926，可以照 jevlike v3 的做法，低信心的題再交給 26B。
4. **MediaPipe Decision Maker（GLiNER、EG2）和 NLI 不能當四選一的狀態判讀器。**
   - 準確率 35–48%，而且偏向少數幾類：GLiNER 偏選 D，EG2 幾乎不選 C，NLI 偏選 C。
   - v2.1 裡 GLiNER 在 T6／T7／T8 的 AUROC 很高，原因是 v2.1 只要求比對新舊兩版的排序，不要求讀懂規則、做四選一。
   - 照規格用的是預設設定，`normalize_prior` 與題目措辭都沒有調整，所以這是「預設設定下」的結果。
5. **日期不必先算好再交給 26B**（H15 不成立），但 H-dat 仍是每個 LLM 最難的題型：26B 90.7%，GD1 92.6%。
6. **變更偵測**：GD1 和 26B 的 AUROC 都在 99 以上。用 26B 時，「兩段各自判斷再比較」在嚴格的零誤報門檻下召回比較高（86.9% 對 48.6%）。各段的判斷結果也可以快取。

## 建議的架構（依 v0.3）

- **單段狀態判讀**：用 J-26B；或在可接受少量準確率損失時，改用 E4B → 26B 級聯。
  - 級聯在既有預測上直接計算，見 [cascade.md](cascade.md)。
  - 照「不損失準確率」的規則選門檻，55% 的題要交給 26B，平均延遲反而比只用 26B 慢。
  - 用 jevlike 的既有門檻 τ = 0.999：測試集 96.7%（比 26B 少 0.7 點），16% 交給 26B，平均快約 36%。
- **變更偵測**：對每段文字做一次 26B 判斷並快取，新舊兩版各自查表再比較。
- **GD1**：不進管線，只當上限參考；如果之後要上雲，這批資料已經證明它可以打平 26B。
- **GLiNER、EG2、NLI**：退出判讀層。EG2 的 old/new 標籤距離（C）在 P 任務的 AUROC 也只有 68.3。
- **還沒做**：真實文件驗證，以及照 jevlike v3 的方式量 E4B → 26B 級聯的實際覆蓋率。

## 限制

- 合成資料；gold 由 Claude 出題並由 Claude 盲判，沒有人工覆核。
- GD1 是託管模型，無法鎖定版本。
- MediaPipe 的三個 backend 有 512 token 的視窗限制，長文件題記為缺值。
- 校準集只有 68 組 P 負例，「1% 誤報」門檻和「0% 誤報」門檻相同。
- 延遲在三種機器上量測：Modal L4、本容器 CPU、Google 雲端。不同機器之間只能比較量級。
